# Release implementation validation

Local validation completed on 2026-10-17:

- Go race/static checks passed across API, commands, internal packages and fixtures. Focused checks additionally cover actual HTTP-01 issuance against a local RFC 8555 service, cancellation/expiry/cleanup, administrator boundaries, migration history/checksums, populated up/down paths, transactional failure, encrypted restoration and stale-update-request removal.
- Updater tests cover session-bound plans, expiry/replay, trusted consecutive releases, fresh backup input, destructive approval, secret redaction, preflight failure, safe rollback, recovery_required and restart after the backup/replacement checkpoint. Restart tests verify one backup and one installation revision increment. Maintenance tests defer late deployment claims, and the job-drain deadline survives updater restarts.
- Six frontend unit tests, all 118 desktop/mobile browser checks, regenerated OpenAPI/TypeScript/sqlc drift checks and production frontend builds passed. Dashboard access/System updates browser coverage includes consent, manual DNS, failures/retries, permissions, migration preview, destructive confirmation, backup download and progress reconnection in light/dark themes. Provider and update UI scenarios use fake API responses; installation, invitations and viewer boundaries also exercise the real API in a disposable installation.
- Installer tests passed in a disposable container without Docker access: successful setup flow, resumption, key preservation, single bootstrap-token presentation, damaged files, absent checksums and conflicting installation refusal.
- All four SSH/Linux integration suites passed against real Docker, Compose and HAProxy 3.4: direct Compose, exact-image rollback and volume preservation; readiness/replacement and protocols; hostname maps and generation recovery; direct-IP networking, replicas, fixed IPv4/IPv6 addresses, hostnames and cleanup. Protocol checks include continuous requests, WebSockets, gRPC streaming and TCP termination/passthrough.
- Native Linux HTTPS/bootstrap and local deployment tests passed, including terminal WebSockets, SSE logs, renewal failure, protected cleanup and rollback. The real updater fixture passed both `0.1.0 → 0.1.1 → 0.1.0` steps, creating encrypted backups and replacing both packaged components without replacing HAProxy or interrupting unrelated application traffic. A second run passed with an explicit `127.0.0.2` web bind; probe unit tests also cover IPv6-only and public-address bindings. Release manifests are synthetic and map registry pins to local images; Docker, migration commands, backups and HTTPS verification are real.
- Both binaries cross-built for Linux ARM64, and workflow linting plus release-artifact tests passed. Publication checks require both AMD64/ARM64 image metadata and anonymous pulls. GitHub publication, anonymous GHCR pulls and live Let's Encrypt issuance were not run: repository access returned 404, and live issuance requires a reachable configured host. The initial release has no published predecessor; subsequent publication runs the preceding published schema in both directions, including explicit refusal of unsupported reverse paths.

External Go/package services intermittently returned truncated downloads. Local image validation reused the verified dependency cache when necessary. The development dashboard was refreshed to `0.1.0-dev` and its health/version endpoints verified; existing resource counts and its running application were preserved.

Tests use disposable databases/engines and fake Git, DNS, ACME and release services by default. No real deployment resources are reset. See [development](development.md) for reproducible commands and [releases](releases.md) for repository publication permissions.
